# 功能全景

AIHelper 将推理、人工标注、结果复核、评分、版本分析和数据交付连接起来。本文按 2026-10-28 私有工作区源码与文档整理，包含主程序和独立脚本；描述的是已有实现范围，不代表每个功能均完成了本次设备实跑验收。

文中的脚本名用于说明功能归属。本公开仓库仅提供展示文档与素材，不包含对应源码、模型、程序数据或可直接运行的完整产品。

![AIHelper 功能与产物关系示意](../assets/workflow.svg)

## 1. 图源与推理调试

| 功能 | 已有能力 |
| :--- | :--- |
| 图源输入 | 程序目录与 SQLite、DZI、旧 FOV、整板图片、普通图片、多光源 |
| 大图查看 | 缩放、平移、局部高清读取、显示缓存与推理输入分离 |
| SMT 流程 | 检测 → 分类 → DIR 方向校正 → IC 子结构 → OCR |
| 其他工艺 | THT、DIP 模型与流程配置，使用各自支持的阶段组合 |
| 调试范围 | 整板、区域、单阶段及独立算法任务，按任务条件选择 |
| 过程观察 | 切块与复检区域、运行状态、日志、耗时及阶段进度 |
| 结果查看 | 目标列表与画布联动、父子结果、详情查看与复制 |

SMT 的 DIR 校正生产父框；Stage2 开启 GT 输入时仍使用 GT 父框。工艺支持不等于所有模型效果均已验收，例如 THT 的图源与训练条件仍需通过对应样本验证。

## 2. 浏览器标注

标注页由 `benchmark_local_editor.html` 与本机标注服务共同提供。

- **层级标注**：Stage1 元件、Stage2 子结构、OCR 文本行及其关联。
- **旋转框编辑**：绘制、移动、缩放、旋转，精确修改中心、宽高与角度。
- **编辑操作**：多选、复制、剪切、粘贴、删除、撤销及快捷键。
- **导航与显示**：整板和裁图切换、元件前后导航、类别筛选、图层显隐、透明度与画质控制。
- **OCR 标注**：主文本、多个可接受文本、阅读方向。
- **评测范围**：完全排除、只排除分类判断，以及 ignore 标记的评测处理。
- **保存保护**：父子引用检查、revision 冲突检测、备份、原子写入和三阶段联合保存。

Stage2 需要关联一级父项；OCR 还需关联有效的二级本体。标注保存依赖本机服务，单独复制 HTML 文件不能替代完整标注环境。

## 3. 可视化与软件语义复核

| 视图 | 用途 |
| :--- | :--- |
| 桌面结果画布 | 查看检测框、方向、子结构、OCR 和目标详情 |
| HTML 预测页 | 缩放平移整板、切换阶段图层、查看类别统计、定位元件 |
| HTML 评分页 | 叠加 GT 与预测，筛选漏检、误检、分类错误和定位质量，跳转到目标 |
| CLS 专项视图 | 查看分类输入来源、分类结果、错误或失败项 |
| OCR 专项视图 | 查看文本框、识别文字、阅读方向和评测差异 |
| 软件语义工作区 | 查看最终检测树、补框前后联动对照、SQLite 程序检测树及用途分组 |

软件语义包含方向结果复用、检测框生成、补框、角色刷新和结果保存。原始候选、最终语义框与补出框可以区分查看。

## 4. 独立评测与单程序报告

`modules/evaluation` 提供匹配和指标计算，`benchmark_report_live.html` 展示报告。

| 对象 | 评测内容 |
| :--- | :--- |
| Stage1 检测 | 几何匹配、Precision／Recall／F1、漏检、误检、框质量与检测验收分 |
| CLS 分类 | 独立分类准确率、错分与失败、GT／预测框输入来源 |
| Stage2 子结构 | 同父项范围内的匹配、类别指标、定位质量与漏检惩罚 |
| OCR | 检测、识别、阅读方向，以及独立的端到端诊断 |
| 框质量 | IoU、GT 覆盖、预测有效覆盖、中心、宽高和角度偏差 |

具备已有结果和所需 GT 的阶段可以直接评估，导入结果也可参与；已执行但检测为零的阶段仍可计分。OCR GT 评测需要完整的关联标注。检测与分类指标分开计算，避免混淆检出问题与分类问题。

DIR 与一级 GT 的角度差仅作诊断。评分和回归工具不会自动更新 GT 或基线；人工标注是独立的维护行为。

## 5. 综合评分、版本对比与开发诊断

### 工具组成

| 工具 | 输入与职责 | 主要输出 |
| :--- | :--- | :--- |
| `综合评分.py` | 读取一个或多个版本目录下的评分 JSON，整理程序、阶段、模型和类别记录 | 汇总数据、HTML 报告与 Excel 工作簿 |
| `生成版本对比驾驶舱.py` | 消费汇总数据，展示单版本表现或版本对比 | 综合评分／版本对比驾驶舱 |
| `生成开发调试指标.py` | 汇总分类表现与几何诊断，按风险排序 | 开发调试指标 HTML |
| `生成工作簿.mjs` | 将汇总数据组织为工作簿 | 综合评分 Excel |
| `benchmark_aggregate_report.py` | 发现多程序评分记录，并兼容读取既有报告 | 批次综合指标 HTML |

`综合评分.py` 与三个配套生成器位于私有仓库 `integrations/综合评分/`；批次汇总工具位于 `benchmark/`。这些工具处理已有评测产物，不需要为了汇总再执行一轮模型推理。

### 报告如何帮助排查

1. 按版本和阶段查看表现，区分检测、分类、子结构和 OCR。
2. 按元件类别查看指标，避免整体均值掩盖局部问题。
3. 在优先问题列表中定位具体程序、阶段和异常指标。
4. 查看中心、尺寸、角度和覆盖误差分布，识别误差集中范围。
5. 从程序明细链接回源报告，在图像上复核目标。

开发调试页还展示加权指标、程序中位数与最差程序，支持版本／阶段筛选和程序／元件搜索。各阶段保持独立统计，不混合成一个跨任务总分。

### 使用边界

- 原始运行记录保留；比较默认选择对应的最新批次，并标记输入口径。
- 新一次汇总写入新的运行目录。
- `--check` 可检查输入和依赖，`--html-only` 可仅生成两份 HTML。
- Excel 生成依赖 Node.js 与 `@oai/artifact-tool`。
- 下钻链接需要对应的源报告与图像资源仍可访问；汇总 HTML 不等于自动打包了所有源文件。
- 历史评分记录的字段和口径可能不同，展示时需保留来源与适用范围。

## 6. 便携标注与结果交付

| 产物 | 用途 |
| :--- | :--- |
| Result v2 | 保存一级父项、二级与 OCR 明细、模型及输入来源，支持重新加载 |
| 程序结果转换 | 将 SQLite 程序元件与检测结构转换为可导入结果 |
| 可视化图片与 HTML | 供查看、讨论和复核，保留相关资源依赖 |
| `.aitask` | 保存程序图源、已有 GT、冻结预测和任务清单 |
| Windows 便携标注 ZIP | 包含任务、标注运行时、启动与 GT 导出脚本 |

便携包需完整解压后使用。中途换电脑应交接整个工作目录，完成后交回完整 GT 目录。同一个包采用顺序交接，不支持多人并发编辑或自动合并。

## 7. 批处理与外部数据采集

- **程序批处理**：程序发现与去重、阶段及模型配置、GT 输入模式、完成记录、失败明细、评分和标注包发布。
- **普通图片批处理**：递归扫描、断点续跑、起点与数量控制、逐图持久化、机器可读进度。
- **数据采集协议**：通过子进程和 UTF-8 JSON 对接板级 Stage1＋分类、普通图片 OBB 或 Stage2 OBB。
- **调用方支持**：启动脚本、协议 schema、结果示例和标准库子进程客户端。
- **DIP 样本收集**：`collect_dip_stage1_by_class.py` 运行检测，按预测类别保存原生 Rgb 裁图与清单。

数据采集接口使用稳定结果契约，不要求调用方导入内部模块。裁图收集服务于样本整理和复核，本项目的这些功能不包含模型训练闭环。

## 8. 连锡与独立算法分支

独立 AI 检测计划允许在板图或普通图片上定义旋转区域，运行 OCR、连锡目标检测或分割，并保存每次运行结果。

连锡模块根据相邻 Pad 构造间隙区域，区分目标检测与分割所需输入，并将结果映射回图像。原生接入参考保留 C ABI、C++／C# 示例、构建脚本和运行时校验；其定位是离线接入参考，现场阈值、模型效果和性能需单独验收。
