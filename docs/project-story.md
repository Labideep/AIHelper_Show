# 项目故事

## 背景

AOI 视觉流程通常包含多种图源、多个模型和大量后处理规则。算法调试工具如果只关注“模型能否跑起来”，很难解释生产流程中的结果差异，也难以支撑稳定的批量回归。

## 目标

AIHelper 希望建立一条从输入到最终结果都可追溯的本地验证链路：同一套流程既能在桌面界面中逐阶段观察，也能用于批量执行和基线对比。

## 主要挑战

- 多阶段模型之间存在父子关系和坐标依赖。
- 大图切块、缩放、旋转和透视裁切会累积几何误差。
- GUI、批处理和独立调用容易形成不同默认行为。
- GPU 模型加载、并发和释放会影响吞吐及稳定性。
- 生产语义与纯模型结果并不完全等价，需要明确边界。

## 解决思路

项目用统一的应用流水线承接所有入口，通过结构化上下文传递阶段证据；用稳定的板级坐标和父子身份连接检测、分类、方向、子结构与 OCR；用不可自动修改的基线和差异报告保障回归可信度。

## 适合在面试中展开的内容

1. 如何把遗留 GUI 调用收敛到统一应用服务；
2. 如何保证旋转框跨缩放和裁切后的坐标一致性；
3. 如何设计后台任务事件，避免界面线程竞态；
4. 如何区分模型输出、后处理结果和生产软件语义；
5. 如何建立不会自动掩盖差异的回归验证机制。

## 展示边界

公开仓库只描述问题、设计与结果。具体业务规则、模型资产、生产数据、内部运行参数和完整实现保留在私有环境中，可在授权场景下进行代码走读或现场演示。
